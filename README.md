# CloudShift — Genesys Cloud Configuration Promoter

CloudShift is a local administrative workspace for exporting Genesys Cloud configuration as Terraform, reconciling it against another organization, reviewing a saved plan, and applying only the approved plan.

Version 4 replaces repeated OAuth prompts with reusable local environment profiles. Client secrets remain on the local runner and are never returned to the browser.

Version 4.0.1 also permits the production UI's loopback origin when the runner
uses a custom or default port. This prevents ZIP inspection from failing with a
generic browser `Failed to fetch` message in production mode.

Version 4.0.2 normalizes imported Terraform modules by removing setup blocks
from exported files before writing the single destination-specific
`zz-promoter-provider.tf`. This prevents duplicate `required_providers`
initialization errors.

## What changed in version 4

- Save Genesys Cloud environment credentials once in a local, Git-ignored vault.
- Select a configured environment from the UI instead of repeatedly entering OAuth credentials.
- Verify and display the actual Genesys organization name and ID.
- Bind every job and saved plan to the authenticated session, organization, and region.
- Recheck the destination organization immediately before `terraform apply`.
- Clear stale plans and mappings when the connection or package changes.
- Validate uploaded packages and reject path traversal, executable files, modules, provisioners, backends, and non-Genesys providers/resources.
- Include `promotion-manifest.json` and `unresolved-references.json` in exported ZIPs.
- Add Terraform process timeouts, temporary-job cleanup, secret redaction, and authenticated downloads.
- Serve the production frontend from the Express runner.
- Offer a Terraform state backup after a successful apply.
- Add automated tests and pin Node dependency versions.
- Redesign the interface for clearer environment, export, reconciliation, plan, and approval stages.

## Requirements

- Node.js 22.12 or newer
- npm
- Terraform CLI available in `PATH`
- Network access to the Terraform Registry and the selected Genesys Cloud region
- Genesys Cloud OAuth clients with the permissions needed for the resource types being exported or changed

Confirm Terraform is installed:

```bash
terraform version
```

## Install and run

```bash
git clone https://github.com/ChrisAstorga/Terraform_UI.git
cd Terraform_UI
npm ci
npm run dev
```

Development mode opens the React frontend on `http://localhost:5173` and runs the local API on `http://127.0.0.1:8787`.

For a production-style local run:

```bash
npm start
```

This builds the frontend, starts the runner, and serves the complete application from `http://127.0.0.1:8787`.

## Configure environments

1. Open **Environment**.
2. Select **Add environment**.
3. Enter a friendly name, Genesys region, OAuth client ID, and OAuth client secret.
4. Save the profile.
5. Select it from the environment dropdown and click **Verify and connect**.

Credentials are stored in:

```text
config/environments.local.json
```

The file is excluded by `.gitignore` and is written with restrictive permissions where the operating system supports them. Do not remove it from `.gitignore`, publish it, email it, or commit it to GitHub.

You can optionally seed the vault manually:

```bash
cp config/environments.example.json config/environments.local.json
```

Then replace the placeholders locally. Restart the runner after editing the file outside the application.

To keep the vault elsewhere, set `GENESYS_ENVIRONMENTS_FILE` to a relative or absolute path before starting the runner.

## Workflow

### 1. Connect

CloudShift uses `genesyscloud_organizations_me` to authenticate the configured OAuth client and read the actual organization ID and name. A local, in-memory session is then created for that exact environment profile.

Sessions expire after eight hours. Updating or deleting a saved environment immediately invalidates its active sessions.

### 2. Export

- Select resource types from the catalog.
- Optionally filter object names with a regular expression.
- Choose selected resources only or include dependencies.
- Start the export.
- Download the generated ZIP.

The runner creates a `genesyscloud_tf_export` configuration, executes Terraform, consolidates the exported top-level Terraform configuration into `genesyscloud.tf`, filters obvious secret variable names, and creates a portable ZIP.

Every version 4 ZIP includes:

- `genesyscloud.tf`
- `promotion-manifest.json`
- `unresolved-references.json`
- Any supporting files exported by the Genesys Cloud provider

### 3. Inspect and reconcile

Upload a ZIP generated by this application. Resources default to **Create**.

The ZIP may contain only `genesyscloud.tf`, but keeping
`promotion-manifest.json` and `unresolved-references.json` is recommended. They
record the source organization and identify hard-coded GUID references. The
runner accepts these JSON files and does not treat them as managed resources.

When testing only one exported object, you can remove the other Terraform
resource blocks and re-create the ZIP. Keep the Terraform file at the ZIP root
or inside a single folder. On Windows, select the files and choose **Compress to
ZIP file**; do not upload the `.tf` file directly.

For an object that already exists in the destination:

- Run destination discovery and use an exact match, or
- Select **Update** and enter the destination object ID manually.

Mappings can be exported to CSV, edited, and imported back into the application.

### 4. Plan

CloudShift extracts the package into an isolated job workspace, validates its contents, normalizes the provider to the active destination region, imports mappings marked **Update**, and generates a saved `promotion.tfplan`.

Changing a mapping or package invalidates the current UI plan and requires a new plan.

### 5. Apply

Before apply, the user must type the destination organization name. The backend then:

1. Confirms that the active session owns the plan.
2. Confirms that the organization and region match the plan target.
3. Recalculates the saved plan SHA-256 checksum.
4. Authenticates again and reads the destination organization identity.
5. Applies the unchanged saved plan only if every check passes.

After success, download the Terraform state backup and store it securely. Terraform state can contain sensitive configuration values.

## Local security model

CloudShift intentionally binds the runner to `127.0.0.1`. It is designed for a trusted administrator on a local workstation—not as an internet-facing multi-user service.

Important practices:

- Import only packages created by a trusted CloudShift instance.
- Keep `config/environments.local.json` and downloaded state backups private.
- Use least-privilege OAuth clients for each environment.
- Review every Terraform plan, especially any destroy count.
- Do not expose port `8787` through a public reverse proxy.
- Rotate OAuth secrets according to your organization’s security policy.

The package validator reduces risk but is not a general-purpose sandbox for arbitrary Terraform.

## Temporary data and cleanup

Jobs, uploaded packages, provider cache files, plans, and state are stored under the operating system temporary directory in `genesys-transfer-runner`.

- Completed and failed job workspaces expire after 24 hours.
- Session and job records are in memory and are lost when the runner restarts.
- Terraform state backups are available only while the corresponding job workspace exists.

## API overview

| Endpoint | Purpose |
| --- | --- |
| `GET /api/health` | Check Terraform availability |
| `GET /api/environments` | List safe, masked environment profiles |
| `POST /api/environments` | Create or update a local environment profile |
| `DELETE /api/environments/:id` | Remove a local environment profile |
| `POST /api/connections/test` | Authenticate and create an organization-bound session |
| `DELETE /api/sessions/current` | End the active session |
| `POST /api/exports` | Start an authenticated export job |
| `POST /api/imports/inspect` | Validate and inspect a ZIP package |
| `POST /api/imports/discover` | Discover destination objects by configured name |
| `POST /api/imports/plan` | Reconcile resources and create a saved plan |
| `POST /api/imports/:id/apply` | Verify and apply the saved plan |
| `GET /api/jobs/:id` | Poll an authenticated job |
| `GET /api/jobs/:id/download` | Download an export package |
| `GET /api/jobs/:id/state` | Download a post-apply state backup |

Authenticated endpoints require the in-memory session identifier in the `X-Session-Id` request header. The React interface handles this automatically.

## Testing limitations

The included automated tests cover environment secret handling and package validation. A full end-to-end test additionally requires Terraform and dedicated Genesys Cloud test organizations with suitable OAuth permissions.
